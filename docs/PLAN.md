# PLAN — Drop `golang.org/x/crypto` dependency

## Why

`golang.org/x/crypto` is listed in `go.mod` solely because `bcrypt/bcrypt_test.go` imports
`golang.org/x/crypto/bcrypt` in `TestInteropWithXCrypto` to dynamically compare hashes.
The library runtime itself (`webtyp/crypto/bcrypt`, `webtyp/crypto/blowfish`) is already a 100%
pure-Go, stdlib-free port. Importing an external third-party dependency in tests pollutes `go.mod`
and breaks the zero-dependency promise of `webtyp/crypto` for browser and edge WASM builds.

Replacing that single dynamic test with a precomputed static test vector decouples the repository
completely, allowing `go mod tidy` to purge `golang.org/x/crypto` from `go.mod` and `go.sum`.

## Stage 1 — `bcrypt/bcrypt_test.go`

In `bcrypt/bcrypt_test.go`:
1. Remove `import xbcrypt "golang.org/x/crypto/bcrypt"`.
2. Rewrite `TestInteropWithXCrypto` to verify against a static known vector without importing `x/crypto`:

```go
func TestInteropWithXCrypto(t *testing.T) {
	pass := []byte("interop-password")
	// Known standard bcrypt vector generated by golang.org/x/crypto/bcrypt (cost 4):
	xHash := []byte("$2a$04$nnaG3N9q7O6f3b9mfdacPuR1z9TLJ8GYnSwi7LEtNm8lS/Jce/X3.")

	err := bcrypt.CompareHashAndPassword(xHash, pass)
	if err != nil {
		t.Errorf("CompareHashAndPassword failed for x/crypto known vector: %v", err)
	}

	ourHash, err := bcrypt.GenerateFromPassword(pass, bcrypt.MinCost)
	if err != nil {
		t.Fatalf("our GenerateFromPassword error: %v", err)
	}

	err = bcrypt.CompareHashAndPassword(ourHash, pass)
	if err != nil {
		t.Errorf("CompareHashAndPassword failed for our generated hash: %v", err)
	}
}
```
